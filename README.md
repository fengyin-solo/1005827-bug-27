# 城市排水防涝泵站运行与内涝处置管理平台

面向排水泵站台账、泵组运行、排水管网与检查井养护、水位雨量监测、内涝点处置、闸门调度与抢险队出动的一体化城市排水防涝运行管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `drainage-pump:entries` 这一项，或调用 `resetModule(模块)`。

## 检查井责任口径（manhole）

检查井模块在通用骨架之上单独收口，规则集中在 `src/data/manhole-domain.ts`（纯规则）与
`src/api/manhole-service.ts`（唯一写入口），页面不做业务判断：

- **归属只认所属管段**：每口井解析到一个管段（管段花名册含旧层级别名，用于给既有档认亲，
  不改写既有档原值）；只有本管段养护工能登记、改井盖状况与井深、驱动状态流转，跨管段提交
  一律退回，回执写明「拦截在【某关口】」。
- **办结受控**：状态为「已养护」的井整条受控、只读，改动与流转都挡在【办结受控】关口。
- **同管段井编号唯一**：重号登记挡在【重号】关口；跨管段同编号不构成重号。
- **井体状态同源**：井体状态只由井盖状况推导（完好→井况正常、破损→井体破损、缺失→井口危险），
  与井盖状况/井深在同一笔提交里原子更新，列表与详情读同一份数据。
- **并发仲裁**：同一口井（同管段+同井编号）并发提交时，归属方优先于跨管段方；同归属只认先到
  那一版（乐观锁版本号）。冲突的一条挡在【并发仲裁】/【乐观锁】关口并写留痕。
- **审计留痕**：谁、什么时候、想动哪口井、拦在哪道关口、结果如何，都写入
  `drainage-pump:audit:manhole`，页面「责任审计留痕」可倒查。
- **既有档兼容**：首次读取时对老数据做一次迁移——原字段/原层级值原样保留（`原所属管段`、
  `原井体状态` 留底），仅补齐责任域字段（档别标记 `legacy`、`segmentCode`、版本号），并按新
  归属口径把井体状态重算一次；迁移本身也逐条留痕。新登记井标记为责任档（`owned`）。

责任规则的端到端校验（41 项，localStorage 打桩、Node 内运行）：

```bash
cd frontend
npm run check:manhole
```
